# Local voice input

The signed-in Carmelita chat offers microphone dictation. Recording, playback,
transcription review and insertion into the existing draft are separate actions.
Only the normal Send action submits text to the chat. Audio is never submitted to
a transcription API or included in a chat request.

## Processing and recovery

- MediaRecorder selects Opus/WebM or MP4 when supported and releases microphone
  tracks on stop, cancellation, timeout, error or owner change.
- Recordings stop after 120 seconds or approximately 3 MiB. Native final chunks
  are retained; a limit or interruption is shown explicitly.
- Chunks are saved incrementally to IndexedDB, keyed by the authenticated owner
  and recording ID. Recovery ignores old writers and expires a recording on its
  next access after 24 hours. The same browser profile is required for recovery.
- Storage writes and final saving are bounded. If storage is unavailable, the
  in-memory recording remains playable and downloadable, with an explicit warning.
  Browser eviction, cleared storage or termination before a chunk is written can
  still lose audio; recovery is not a guarantee of durable cloud storage.
- Starting Whisper, canceling inference and retrying never discard the recording.
  The transcript is editable. Insertion refuses messages above 2000 characters
  rather than truncating or sending them automatically.

## Engine

Transformers.js 3.8.1 offers two pinned multilingual models with q8 weights:
Whisper Base (`onnx-community/whisper-base`, revision
`1846881b6b3a3024392c1eea3ad983695bc23925`) is the UI default; Whisper Tiny
(`onnx-community/whisper-tiny`, revision
`ff4177021cc41f7db950912b73ea4fdf7d01d8e7`) remains an explicit lighter option.
Base is a larger recognition model, not a guarantee of phone accuracy. WASM runs
in a dedicated worker using one thread. The user explicitly selects the spoken
language (Spanish, English or Portuguese), independently of the interface locale.
Transcribe remains disabled until a language is selected; the worker rejects
missing/unsupported languages instead of silently falling back. No automatic
language detection is promised. The WASM-only ONNX build avoids GPU-specific assets.

Successful transcripts retain their spoken-language and model metadata locally.
Reload restores it, and changing the interface language does not change it.
Selecting another language/model blocks insertion of the previous transcript until
its settings are restored or transcription succeeds again. A new attempt invalidates
the previous result, retaining its text and original audio; cancellation/error/reload
cannot present it as the new result. Legacy audio
and text without metadata remain recoverable but require choosing a language and
retranscribing before insertion. No storage schema migration is required.

The model is downloaded from Hugging Face only after Transcribe is selected;
the initial engine/model transfer is roughly 90 MB for Base or 60 MB for Tiny.
Switching model terminates the old worker instead of retaining both engines.
No silent fallback changes the selected model. Public model weights use
the browser cache. No API key or paid transcription service is needed. Phone
speed, memory and recognition quality require device acceptance; technical
names, tickers and addresses must be reviewed before sending. Decoded 16 kHz PCM
has quiet leading/trailing edges trimmed with 500 ms padding; internal pauses and
the downloadable recording are retained. This energy check is not a speech detector
and cannot establish transcript correctness.

Build-generated worker, WASM and license files live in `public/voice`, are ignored
by Git and are generated by `predev` and `prebuild`. Updating the engine requires
regenerating these files and checking real browser inference again.

## Acceptance

Unit coverage exercises chunk ordering, final-chunk saving, quota failure,
owner separation, stale writers, expiration, cancellation of late permission,
interrupted recovery, duration limits, worker cancellation/retry, warm reuse and
draft length preservation, spoken-language/model validation, model-switch cleanup,
quiet-edge preparation and recovery after an invalidated retry.
A local fixture uses real chat/voice components,
fake identities/APIs and Windows-generated Spanish speech; it does not use a
personal microphone or database. The Spanish fixture must transcribe correctly
with the interface set to Portuguese; verify reload and interface-language
switching preserve settings, and insertion makes no chat POST. Repeat with a
53-second fixture containing two Spanish phrases and long quiet edges, and confirm
canceling a new attempt blocks the previous result after reload. The user's actual
phone recording has not been reproduced; a correct synthetic fixture is insufficient
to close real-phone acceptance.

Current accuracy status: **failed / experimental**. The user reports Spanish speech
becoming unrelated English text even after selecting Spanish. Base transcribed the
short synthetic Spanish sample correctly, but in the long fixture it misspelled
`billeteras` and omitted a repeated utterance. This alternative is for isolated QA
comparison, not accepted production recognition. Do not mark this fixed from unit
tests, a short synthetic recording or successful insertion. Retest on the phone
with a known utterance and compare the spoken words to the editable transcript.

Before publishing, verify on a real phone: grant microphone permission, record
10 seconds in Spanish with the interface in Portuguese, stop, play back, select
Español as audio language, transcribe, edit, use text, manually send, recover
after reload, cancel/retry and check the keyboard/composer. Also test denied
permission and first-download failure. This feature does not approve the
outstanding ChatGPT, OAuth-expiry or independent-onboarding acceptance gates.
